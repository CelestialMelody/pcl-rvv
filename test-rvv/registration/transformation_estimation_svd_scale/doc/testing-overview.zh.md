## 测试类型定义

| 类型 | 本 topic 中的含义 |
| --- | --- |
| correctness aggregate（正确性汇总入口） | Std/RVV 两个构建都运行完整 gtest，证明 production public path、fallback boundary 和 diagnostic helper 与 reference / fallback baseline 对齐。 |
| QEMU smoke（QEMU 小型验证） | 只验证 build、case label、日志形状、`max_reference_error` 和 Evidence Doctor 输入；不作为性能证据。 |
| board smoke（板卡小型验证） | 确认 RVV test binary 在板卡上能运行并通过 correctness。 |
| board repeated（板卡重复采集） | 使用多 run summary 和 Evidence Doctor 支撑 diagnostic 或 production direct performance 判断。 |
| production direct（真实生产路径证据） | Phase 031 覆盖真实 public ordered overload dispatch、fallback 和 production bench；Phase 043 覆盖 row-source public overload；Phase 047、Phase 061、Phase 065 和 Phase 067 覆盖有界 production branch；当前均已采纳。 |

## 测试流程

1. 先运行 `run_test_compare`，确认 Std/RVV correctness。
2. 再做 QEMU bench smoke 和 Evidence Doctor，只检查日志形状与 manifest。
3. 需要性能结论时运行 board smoke 和 board repeated，生成 summary / manifest / Evidence Doctor。
4. 写 EvidenceDecision 前运行 `evidence_status`，检查 registry 新鲜度。
5. 进入 production integration loop 后，重新按 production direct target 执行 correctness、asm、board repeated 和 doctor；Phase 010 已完成这一轮。
