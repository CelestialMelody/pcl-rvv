## 暂缓 / 拒绝路线

| candidate family | reason | resume condition |
| --- | --- | --- |
| non-organized KNN n-link | `nearestKSearch` 和不规则 neighbor list 会主导成本，首阶段无法把 RVV 公式收益干净外推到 production | 有 profile 证明 KNN 之外公式段占比高，或 organized path 完成后需要覆盖 non-organized public shape。 |
| organized n-link production expansion | 历史 organized n-link component 观察约 `0.98x`，且 graph edge mutation / memory traffic 可能抵消收益；Phase 070 公开入口已经 positive，不需要为解释收益不足而立即重开。 | profile 指向 n-link 成为公开入口主瓶颈，或新的 component repeated board 改变 decision bucket。 |
| color staging production expansion | RGB/RGBA 到 `Color` 的转换可能可批量化，但当前没有 profile 证明它主导公开入口；直接接入会扩大点类型 / layout gate。 | profile 证明 `initCompute` color conversion 占比足够高，并补 RGB/RGBA traits / fallback tests。 |
| GaussianFitter accumulation RVV | Phase 120 显示接入后 RVV `learn_gmms` 中位占比只有 `4.592618%`，且累加会引入分散 bucket、浮点顺序和空 component 语义风险；当前不值得继续自动实现。 | 新 public profile 或 production-detail profile 显示 `learn_gmms` / accumulation 占比重新成为主成本，并先补 Step 4 / Step 5 消融和数值预算。 |
| LMUL / ILP variants for `learnGMMsRVV` | Phase 120 显示当前 `learnGMMsRVV()` 不是剩余主成本；做 RVV-vs-RVV family selection（RVV 实现族选择）不太可能改变公开入口决策。 | 新同边界 profile 显示 `learnGMMsRVV()` 是主要剩余瓶颈，且 A/B 能改变 adopted implementation family。 |
