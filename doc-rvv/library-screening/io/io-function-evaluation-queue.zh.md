## 3. 文件级变化理由

第二轮没有扩大候选池，而是把第一轮的文件级粗筛压缩成函数级队列。归并原则如下：

- 图像颜色转换只建立一个转换族视角：`debayer`、YUV422 和 RGB24 灰度转换按像素公式区分首阶段目标，不为 OpenNI 旧实现重复建立独立 topic。
- 深度 / 视差转换只建立一个深度图转换族视角：通用 `DepthImage` 和 OpenNI 旧 `DepthImage` 共享 `mm -> m`、invalid mask、`constant / depth` 语义。
- OpenNI / OpenNI2 / ONI 帧转点云只建立一个 frame-to-cloud dataflow 视角：优先从仍较清晰的 OpenNI2 / OpenNI 公开 grabber 入口验证，ONI replay 先保留。
- organized compression conversion 作为一个 topic：`OrganizedConversion::convert` 是主公式，`OrganizedPointCloudCompression::encodePointCloud` / `analyzeOrganizedCloud` 是调用与规约边界。
- PCD / PLY / VTK 字段转换统一视为 field-layout conversion 家族：先保留，不把每种文件格式拆成重复 topic。
- LiDAR packet 解码统一视为 packet-to-point family：HDL / VLP / RobotEye / TIM 先保留做 profile 或 production-shaped diagnostic，不为每个 packet 格式直接建立生产优化 topic。

本轮未补入 low。`src/image_ir.cpp`、`src/lzf.cpp`、`src/ascii_io.cpp`、`src/ply/ply_parser.cpp` 等第一轮 low 文件虽然有循环或 I/O 状态机，但没有新的源码证据证明它们应越过当前 38 个 high/mid 基线。
