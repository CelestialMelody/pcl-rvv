# recognition 模块 RVV 第二轮函数评估队列

本文档基于 `doc-rvv/library-screening/modules/recognition-file-candidate-screening.zh.md` 的第一轮 `high/mid` 文件候选，执行第二轮函数级下钻筛选。第二轮筛选本身只形成后续函数级评估队列，不重做第一轮；后续各 topic 的执行状态在第 7 节持续更新，并以对应 topic 的 `test-rvv`、`doc-rvv`、production diff 和板卡证据为准。

## 1. 输入依据

- 指令与模板：`.agents/skills/rvv-screening/SKILL.md`、`screening-criteria.md`、`stage-and-queue-policy.md`、`evidence-boundaries.md`、`function-evaluation-queue-template.md`。
- 第一轮基线：`recognition-file-candidate-screening.zh.md`，统计为 `70` 个源码文件、`5 high / 20 mid / 45 low`。
- 源码范围：`recognition/include/pcl/recognition/**`、`recognition/src/**`。
- 第二轮必查范围：第一轮 `high/mid` 的 `25` 个文件。本轮逐项复核这 `25` 个文件并交代去向。
- 测试入口：`test/recognition/CMakeLists.txt` 只登记 `test_recognition_cg.cpp` 与 `test_recognition_ism.cpp`；CG 测试覆盖 Hough3D / GeometricConsistency，ISM 测试覆盖 train / findObjects。第二轮未运行这些测试。
- benchmark 入口：未发现 `benchmarks/recognition` 目录或 recognition 专项 benchmark。后续 topic 需要自建 production-shaped diagnostic / micro bench。
- 已完成 RVV 主题：第二轮筛选启动时未发现 `test-rvv/recognition` 或 `doc-rvv/recognition` 已完成主题。当前执行清单中，LINEMOD template scoring 和 color gradient modality 已有 adopted production behavior（已采纳生产行为）记录；具体事实以各 topic 文档为准。

## 3. 文件级变化理由

第二轮没有补入 `low` 文件。第一轮 `low` 中的公开声明头、显式实例化 `.cpp`、数据结构胶水和第三方依赖与当前源码一致；真实循环已由对应 `high/mid` 行覆盖。

主题归并只用于共享判断，不改变后续按文件推进的要求：

| 主题簇 | 共享判断 |
| ------ | -------- |
| LINEMOD / modality 图像链路 | `src/linemod.cpp` 已有 `__SSE2__` 分支，`matchTemplates` / `detectTemplates` 的 energy map、linearized map、score scan 是直接匹配主路径，优先建议。`color_gradient_modality.h` 与 `surface_normal_modality.h` 是模板输入的 organized 大图像预处理，建议做 production-shaped diagnostic。`impl/linemod/line_rgbd.hpp` 是 RGB-D wrapper / refinement / clustering 组合路径，先保留，不抢在核心 LINEMOD 与 modality 前实施。 |
| DOTMOD 图像链路 | `src/dotmod.cpp` 直接滑窗匹配，`color_gradient_dot_modality.h` 生成 dominant quantized map，两者均建议进入函数级评估。`quantized_map.h` 的 `getSubMap` 和 `src/quantizable_modality.cpp` 的 `spreadQuantizedMap` 是共享支撑核，保留为后续 ablation，不静默并入主文件。 |
| color-only modality | `color_modality.h` 有像素级量化和 3x3 filter，但 distance map 是双 pass 顺序依赖，且缺直接 recognition test，保留为后续 modality-family 复筛候选。 |
| CG / Hough | `impl/cg/geometric_consistency.hpp` 的 O(n^2) 几何一致性谓词和 `impl/cg/hough_3d.hpp` 的 vote 生成有 diagnostic 价值，且 `test_recognition_cg.cpp` 可作为入口；但 sort、RANSAC rejector、Hough accumulator scatter 和 maxima 输出顺序稀释主成本，因此保留。`src/cg/hough_3d.cpp` 是 HoughSpace 支撑文件，不单独排入建议。 |
| occlusion reasoning | `hv/occlusion_reasoning.h` 与 `impl/hv/occlusion_reasoning.hpp` 均含按点投影、深度比较、keep indices 输出的直接 filter loop，主成本覆盖比其它 HV 文件清楚，因此建议分别进入函数级评估。后续仍按两个文件交付证据，不合成一个隐形任务。 |
| hypotheses verification | `hv/hv_go.h`、`impl/hv/greedy_verification.hpp`、`impl/hv/hv_go.hpp`、`impl/hv/hv_papazov.hpp` 局部有 mask / count / cue 片段，但 search、voxel grid、图结构、OpenMP、simulated annealing 或模型间状态主导，当前暂缓。 |
| ISM | `impl/implicit_shape_model.hpp` 有 `findObjects` descriptor-to-cluster 距离、`calculateSigmas` pairwise 距离、`calculateWeights` Gaussian 权重和 vote mean-shift，且 `test_recognition_ism.cpp` 可触达；但 KMeans、feature estimator、Eigen 动态向量和 search 会稀释主成本，先保留。 |
| face detection | `rf_face_utils.h` 的训练统计规约可隔离，保留为 face-family diagnostic；`src/face_detection/rf_face_detector_trainer.cpp` 的 sliding window / forest / vote clustering 缺 recognition CMake test，且 forest evaluator 与聚类状态主导，暂缓。 |
| RANSAC / ICP | `trimmed_icp.h`、`src/ransac_based/model_library.cpp`、`src/ransac_based/obj_rec_ransac.cpp` 都有大循环中的点变换、pair signature 或 hypothesis test，但 nearest search、sort、hash/octree、graph/set、随机采样和输出状态主导，当前不建议独立 RVV 主题。 |
