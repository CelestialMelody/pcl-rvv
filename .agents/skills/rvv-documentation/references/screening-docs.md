# 筛选文档写作

筛选文档服务于队列恢复和人类复核，不承担主题实现事实的长期解释。

## 文件候选筛选

文件候选筛选只形成 `high/mid/low` 文件级粗筛基线。文档必须：

- 说明输入依据和源码范围。
- 覆盖目标模块范围内的源码文件。
- 使用源码事实解释循环规模、算术密度、访存模式、分支复杂度、语义风险和可验证性。
- 明确 high/mid 是函数评估队列必查基线，不代表最终实施全集。
- 明确 low 不代表永久排除。
- 给出 high/mid/low 数量。
- 全量覆盖表一文件一行，不静默遗漏。
- 路径优先使用省略模块公共前缀后的短路径，并在输入范围说明省略前缀；短路径有歧义时使用 repo-relative 路径。
- closeout 说明函数评估队列应读取的下一份文档。

## 函数评估队列

函数评估队列是模块实施说明 / 执行队列。文档必须：

- 逐项交代文件候选筛选 high/mid 候选去向。
- 新增补充候选时说明来源、证据和边界。
- 写完整统计：文件候选筛选总数和 high/mid/low、初始候选基线数量、新增补充候选、第二轮候选总数、三类队列数量、合并/删除/源码冲突数量、high/mid 降级数量。
- 使用主成本覆盖类型：`direct-main-path`、`partial-preprocess`、`tail-compress`、`diagnostic`、`non-standalone`。
- 在“文件级变化理由”逐项说明保持、升级、降级、合并、转入保留候选、暂缓或删除的原因。
- 按 `建议进行 RVV 优化的文件`、`保留实施的候选文件`、`暂缓或不推荐考虑 RVV 优化的文件` 分组。
- 对每个候选下钻到函数入口或函数族。
- 分析表和执行状态表分离。
- 执行表保留 `顺序`、`主题`、`主文件`、`推荐入口 / 第一 RVV 目标`、`状态`、`当前结论 / 下一步条件`，不变成文档索引表。
- 本轮只做筛选和文档；不修改模块源码，不建立专项目录，不运行目标硬件 bench。

## 二轮保留候选复筛

二轮保留候选复筛不做静态函数评估队列重跑，默认只复筛函数评估队列 `3.2 保留实施的候选文件`。只有源码变化、profile 证据或已完成主题证据明确指向漏筛时，才补入 `3.2` 之外候选并说明边界。

保留候选复筛必须先形成已完成主题证据包，再复筛保留候选。

证据包至少包含：

- 主题名和主文件。
- 原始定位。
- 实际覆盖范围。
- 目标硬件结论。
- 正确性证据。
- 反汇编证据。
- 生产接入状态。
- 回退 / 暂缓原因。
- 可复用模式和失败模式。
- 对后续候选的影响。

已完成主题经验总结至少包含：

```text
| 主题 | 主文件 | 函数评估队列原始定位 | 实际覆盖范围 | 目标硬件结论 | 正确性证据 | 反汇编证据 | 生产接入状态 | 回退 / 暂缓原因 |
```

```text
| 模式标签 | 来自哪些已完成主题 | 成立条件 | 失败 / 回退边界 | 对后续候选的影响 |
```

后续候选按 `建议启动函数级评估` 和 `暂缓 / 不单独实施` 分组。`diagnostic`、`bench-only`、`production-shaped diagnostic`、`component ablation` 和 `production direct` 是后续 topic 内的证据路径或 EvidenceDecision 结果，不是保留候选复筛的固定队列名。

筛选统计至少包含保留实施候选输入总数、建议启动函数级评估数量、暂缓 / 不单独实施数量、建议项默认评估路径分布、重新纳入/合并/删除/源码冲突数量。

提交型复筛文档不要写内部 prompt、对话路径或 `chats/` 路径；这些只属于工作日志或入口模板。
